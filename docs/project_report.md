## 2. Как детально работают Детектор и Клинер сейчас

### 2.1. ExtraneousSpeechDetector (Детектор)
Детектор работает на сетке кадров по **10 мс** (80 отсчетов при 8 кГц):
1. **Энергия и VAD**: вычисляется RMS энергия в окне 30 мс со смещением 10 мс. Оценивается динамический порог тишины. Во фреймах тишины вероятности всех трех классов обнуляются.
2. **Межканальная разность уровней (ILD)**: $ILD = 10 \log_{10}(E_A) - 10 \log_{10}(E_B)$. 
   - Если $ILD \gg +6$ дБ — локальный диктор громче (кандидат на `own`).
   - Если $ILD < +6$ дБ и на канале B речь — вероятная наводка (`leak`).
3. **Кросс-корреляция GCC-PHAT**: в окне задержек $[160, 2400]$ отсчетов ($20-300$ мс) ищется пик корреляции между $x_A$ и $x_B$. Высокий пик подтверждает физическое просачивание с задержкой $\tau$.
4. **Остаток адаптивного фильтра (NLMS Ratio)**: измеряет долю энергии $x_A$, которую удается предсказать по $x_B$.
5. **Спектральные дескрипторы**: спектральный центроид, спад энергии выше 1500 Гц и плоскость спектра. У третьего говорящего звук удаленный, более гулкий (высокая реверберация) и с завалом верхних частот.
6. **Классификатор `_DetectorNet`**: компактный 2-слойный MLP (вход 9 признаков $\to$ 32 нейрона $\to$ 3 выхода), обученный с функцией потерь `BCEWithLogitsLoss`.
7. **Постобработка**:
   - Медианная фильтрация вероятностей окном 50 мс (устраняет дрожание фреймов);
   - Минимальная длина сегмента 80 мс (склеивает микропаузы).

### 2.2. TelephoneAudioCleaner (Клинер)
* **Проблема старой версии**: грубое умножение отсчетов во временной области порождало резкие щелчки («пулеметный» треск) и заикания.
* **Как работает сейчас**:
  1. Выполняется оконное преобразование Фурье (STFT) с окном Ханна (256 отсчетов, шаг 80 отсчетов = 10 мс).
  2. На основе предсказанной вероятности $P(\text{leak})$ строится плавный коэффициент передачи фильтра Винера:
     $$G(f, t) = 1.0 - \text{clip}(P_{\text{leak}} - 0.7 P_{\text{own}}, 0, 1) \cdot (1 - G_{\min})$$
     где $G_{\min} = -22$ дБ (не дает образоваться артефактам «музыкального шума»).
  3. В спектральной области вычисляется $\hat{S}_A(f, t) = S_A(f, t) \cdot G(f, t)$.
  4. Обратное преобразование (iSTFT с перекрытием и сложением Overlap-Add) синтезирует чистый непрерывный сигнал.

## 3. Инструкция по запускам и прослушиванию вне VS Code

### 3.1. Запуск детекции и очистки
```bash
source .venv/bin/activate

# Детекция (на выходе JSON со списком отрезков)
python detect.py input.wav result.json

# Очистка от наводки (на выходе стерео WAV)
python clean.py input.wav clean.wav

# Очистка с генерацией 16 кГц preview-версии
python clean.py input.wav clean.wav --preview clean_preview_16k.wav
```

### 3.2. Как послушать в Linux через терминал
```bash
# 1. Через aplay (стандартная утилита ALSA, всегда работает)
aplay -q clean.wav

# 2. Через paplay (PulseAudio / PipeWire)
paplay clean.wav

# 3. Через ffplay
ffplay -nodisp -autoexit clean.wav

# 4. Через mpv
mpv --no-video clean.wav
```

## 4. Аудит целей из ТЗ: статус выполнения

### 🟢 Полностью сделано (переделывать не нужно)
1. **Интерфейс CLI**:
   - `python detect.py input.wav result.json` — строгий формат JSON с дорожками `"A"` и `"B"`, отрезками `start`, `end`, `label`, `score`.
   - `python clean.py input.wav clean.wav` — очистка стерео-звонка.
2. **Базовое правило (+6 дБ)**: полностью реализовано в `src/baseline.py`, честно рассчитывает порог и служит эталоном сравнения.
3. **Метрики оценки**: F1 с допуском (collar) 50 мс на границах для классов `own`, `leak`, `third` по кадрам 10 мс (`src/metrics.py`).
4. **Спикер-эмбеддер**: скачан и подключен SpeechBrain ECAPA-TDNN (192-dim), замеряет косинусное сходство по отрезкам `own`.
5. **Ограничение скорости RTF**:
   - Требование ТЗ: $\le 1/15 \approx 0.0667$ на 1 ядре CPU.
   - Факт: $RTF \approx 0.010$ (в 6.6 раз быстрее требуемого).

### 🟡 Что сейчас работает, но требует качественного улучшения
1. **Качество детектора в Double Talk и High Leak**:
   - Если владелец канала говорит тише собеседника, покадровый ILD тяготеет к наводке.
2. **Различение третьего диктора**:
   - Добавление динамического сопоставления эмбеддингов повысит точность.
3. **Связка детектора с клинером**:
   - Если детектор ошибается на границах речи или в двойном разговоре, клинер срезает нужные звуки владельца. Повышение качества детектора автоматически сделает звук клинера естественным.

### 🧠 ML-цели по улучшению детектора (Наш главный приоритет)

#### Задача 1. Переход к обработке по чанкам (Chunk-based) с эмбеддинг-атрибуцией
1. **Анкоринг дикторов звонка (Call Enrollment)**: в первые 1-3 секунды звонка на участках высокого $ILD$ ($|ILD| > 10$ дБ) автоматически извлекаем опорные векторы владельца канала A ($\mathbf{e}_A$) и владельца канала B ($\mathbf{e}_B$).
2. **Скользящее чанкование**: разбиваем речь на перекрывающиеся окна (0.5 – 1.0 с, шаг 0.25 с).
3. **Спикер-атрибуция в окне**:
   - $\text{sim}(chunk, \mathbf{e}_A) \approx 1$ и $\text{sim}(chunk, \mathbf{e}_B) \ll 1 \implies \mathbf{own}$;
   - $\text{sim}(chunk, \mathbf{e}_B) \approx 1 \implies \mathbf{leak}$;
   - $\text{sim}(chunk, \mathbf{e}_A) < 0.35$ и $\text{sim}(chunk, \mathbf{e}_B) < 0.35 \implies \mathbf{third}$ (третий говорящий)!

#### Задача 2. Обучение детектора на реалистичных RIR из OpenSLR 28
Заменить аналитические искусственные экспоненты в синтезаторе на выборку из распакованного `data/rirs_noises/RIRS_NOISES/` (комнаты `smallroom`, `mediumroom`, изотропные офисные шумы).

#### Задача 3. Контекстный классификатор (Temporal Context)
Вместо независимой покадровой классификации добавить временной контекст (окно $\pm 5$ кадров / 1D-CNN).
